# Dokploy (Docker image)

Sub2API runs as a Dokploy Docker-image Application with dedicated Dokploy
PostgreSQL and Redis services. Dokploy pulls the published image and does not
need to build this repository.

## Create an isolated project

1. Create a new Dokploy project and use its `production` environment.
2. Add PostgreSQL 18 and Redis 8 inside the environment. Generate strong
   passwords, leave external ports disabled, and deploy both services. Dokploy
   creates persistent volumes for these databases.
3. Add an Application with the **Docker** source. Pin a versioned image digest:

   ```text
   weishaw/sub2api@sha256:9bad8d33cd81813f574cd2b2132fca40cdfcaab8572027cf7131104a1dafec60
   ```

   This is the published `0.2.8` multi-architecture image. Publish a new
   image and update the digest when the project changes.
4. Add a project-specific named volume mounted at `/app/data` on the
   Application to preserve generated configuration and application data.
5. Set the Application environment variables below. Use the **internal service
   names generated by Dokploy** for the database hosts; display names may
   differ. Use the same passwords as the dedicated database services.

   ```dotenv
   AUTO_SETUP=true
   SERVER_HOST=0.0.0.0
   SERVER_PORT=8080
   SERVER_MODE=release
   RUN_MODE=standard
   DATABASE_HOST=<Dokploy PostgreSQL internal service name>
   DATABASE_PORT=5432
   DATABASE_USER=sub2api
   DATABASE_PASSWORD=<PostgreSQL password>
   DATABASE_DBNAME=sub2api
   DATABASE_SSLMODE=disable
   REDIS_HOST=<Dokploy Redis internal service name>
   REDIS_PORT=6379
   REDIS_PASSWORD=<Redis password>
   REDIS_DB=0
   ADMIN_EMAIL=admin@sub2api.local
   JWT_SECRET=<random 32-byte hex value>
   TOTP_ENCRYPTION_KEY=<different random 32-byte hex value>
   TZ=Australia/Sydney
   ```

   Generate each stable secret with `openssl rand -hex 32` and keep it in
   Dokploy. If `ADMIN_PASSWORD` is omitted on first start, Sub2API generates
   it and prints it in the Application logs. Record it securely.
6. Add an HTTPS domain with container port `8080` and deploy. A Dokploy
   generated `sslip.io` domain works without changing DNS. For a custom
   domain, point DNS at the Dokploy host first.
7. Verify `https://<domain>/health` returns HTTP 200 and the web UI loads.

## Operations

- Back up the PostgreSQL, Redis, and Application volumes. The Application
  volume alone is not a database backup.
- Upgrade only this Application's pinned image digest. Back up PostgreSQL
  before an upgrade that may include migrations.
- Keep database external ports closed. The services use Dokploy's network.
- Preserve `JWT_SECRET` and `TOTP_ENCRYPTION_KEY` across redeployments.
  Changing them invalidates sessions or stored 2FA secrets.
